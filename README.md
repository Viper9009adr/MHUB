# Meridian-HUB

Meridian-HUB currently contains two active slices:

- a historical TypeScript/Bun Meridian HUB contract/runtime area, still driven by `package.json`
- a Python AGENTIC-CLI Phase 1 slice in `src/agentic_cli`, which is the current backend-core work validated by TST

This README documents the Python slice from the actual source, and keeps the TypeScript tooling note short so the repository layout stays accurate.

## AGENTIC-CLI Phase 1

The implemented Python surface is a minimal in-process backend core with an optional FastAPI HTTP layer.

What is implemented now:
- `src/agentic_cli/cli.py` exposes `run` and `replay-sla`
- `src/agentic_cli/service.py` accepts validated `RunCommand` input and returns a `RunReceipt`
- `src/agentic_cli/memory.py` stores conversation turns in process and allocates session ids like `session-1`
- `src/agentic_cli/contracts.py` normalizes prompt, optional `session_id`, and string-only metadata
- `src/agentic_cli/replay_sla.py` remains a legacy/parallel CLI surface for replay throughput checks
- `src/orc/dispatch.py` — `OrcDispatch` coordinates run requests through an asyncio task queue to the service
- `src/orc/task_queue.py` — `TaskQueue` backed by `asyncio.Queue` with blocking and non-blocking enqueue/dequeue
- `src/api/app.py` — FastAPI application factory (`create_app`) with dependency injection for `OrcDispatch`
- `src/api/routes/run.py` — FastAPI router factory (`create_run_router`) for the `/api/v1/run` endpoint
- `src/api/schemas/run.py` — Pydantic request/response schemas (`RunRequest`, `RunResponse`, `HealthResponse`, `ErrorResponse`)

### Current behavior

`run` is the backend-core path added for Phase 1.

- A blank `prompt` or blank `--session-id` is rejected as a contract error
- If `--session-id` is omitted, the service allocates `session-<n>`
- Reusing a session id increments `turn_index` for that session
- The local backend returns deterministic output in the form `local:<turn_index>:<prompt>`
- Successful CLI output is emitted as one line: `session_id=... turn_index=... backend=... output=...`

### Hub prompt routing behavior (implemented)

- Recognized hub meta commands remain explicit via `resolve_pre_llm_hub_intent()` in `src/orc/dispatch.py` (`status`, `report`, `location` aliases and hub-context phrase matches).
- In `HubService.AgentStream` (`src/hub/service.py`), those recognized intents bypass LLM orchestration and return deterministic `HubStatus` payloads.
- Free-form prompts that do not match hub meta intent route to the orchestrator path (`ORC` events + `_run_orc_orchestration` stream when an LLM provider is configured).

`replay-sla` is still available, but it is separate from the new `run` path.

- It benchmarks a tiny in-memory replay queue
- It prints `seen=... elapsed_ms=... within_sla=true|false`
- It exits `0` when the SLA is met, `1` when the SLA is missed, and `2` for invalid arguments

### gRPC API Reference

The `HubService` is defined in `proto/hub.proto` (package `meridian.hub.v1`) and implemented in `src/hub/service.py`. It runs on the gRPC port configured via `OrcDaemon` (default `50052`).

All RPCs that operate on a hub return `grpc.StatusCode.NOT_FOUND` with a descriptive detail string when the requested hub or checkpoint does not exist.

#### RPC CreateHub

Create a new hub instance. Returns a unique `hub_id` and `created_at` timestamp.

**Request**: `CreateHubRequest { workspace_id: string, initiator: string }`

**Response**: `CreateHubResponse { hub_id: string, created_at: int64 }`

#### RPC TerminateHub

Terminate an existing hub by ID.

**Request**: `TerminateHubRequest { hub_id: string, reason: string }`

**Response**: `TerminateHubResponse { ok: bool }` — `ok` is `false` if hub not found.

**Error**: `NOT_FOUND` when hub does not exist.

#### RPC JoinHub

Bidirectional streaming RPC for hub membership events. Each `JoinHubRequest` sent by the client produces a `JoinHubEvent` echoed back with a timestamp.

**Request stream**: `JoinHubRequest { hub_id: string, member_id: string, event: string }`

**Response stream**: `JoinHubEvent { hub_id: string, member_id: string, event: string, at: int64 }`

#### RPC TapHub

Read a limited number of recent events from a hub's event stream.

**Request**: `TapHubRequest { hub_id: string, limit: int32 }` — `limit=0` returns all events.

**Response**: `TapHubResponse { events: repeated JoinHubEvent }`

#### RPC CreateCheckpoint

Create a checkpoint for a hub.

**Request**: `CreateCheckpointRequest { hub_id: string, label: string }`

**Response**: `CreateCheckpointResponse { checkpoint_id: string }` — empty string if hub not found.

**Error**: `NOT_FOUND` when hub does not exist.

#### RPC RollbackCheckpoint

Rollback a hub to a previously created checkpoint.

**Request**: `RollbackCheckpointRequest { hub_id: string, checkpoint_id: string }`

**Response**: `RollbackCheckpointResponse { ok: bool }` — `ok` is `false` if checkpoint not found.

**Error**: `NOT_FOUND` when checkpoint does not exist.

#### RPC HubStatus

Get the current state of a hub.

**Request**: `HubStatusRequest { hub_id: string }`

**Response**: `HubStatusResponse { hub_id: string, state: string, updated_at: int64 }` — `state` is `"unknown"` if hub not found.

**Error**: `NOT_FOUND` when hub does not exist.

### TUI — Phase 2 (AGENTIC-CLI-TUI-FIX)

Phase 2 wires the TUI directly to the gRPC `HubService` via a new
`GrpcHubClient` and integrates `StreamRouter` into `HubService` for
per-run outbound queue management.

#### New module: `src/agentic_cli/grpc_client.py`

`GrpcHubClient` is an async gRPC client wrapping `HubServiceStub` for TUI
use. It is instantiated in `OrcChatScreen.__init__` and reuses a single
`grpc.aio` channel for all calls.

| Method | Description |
|---|---|
| `create_hub(workspace_id, initiator)` | Creates a hub; returns `hub_id` string. |
| `stream_prompt(hub_id, run_id, prompt)` | Async generator; yields decoded string chunks from `AgentStream`. |
| `hub_status(hub_id)` | Returns the hub state string (e.g. `"active"`); returns `"unknown"` on gRPC error. |
| `close()` | Closes the gRPC channel. |

Default server address: `localhost:50052` (matches `OrcDaemon` default).

#### hub_id encoding

`stream_prompt` encodes the hub_id into the `agent_id` field of each
`AgentMessage` as:

```
hub:<hub_id>:agent:cli
```

`HubService.AgentStream` decodes this on first message by splitting on `:`
and extracting `parts[1]` as `hub_id` and `parts[3]` as `agent_name`.  This
allows the `StreamRouter` to associate the stream with the correct hub
without a separate metadata field.

#### StreamRouter integration

`HubService.__init__` now creates a `StreamRouter()` singleton stored as
`self._stream_router`.  `AgentStream` calls:

- `_stream_router.register_handler(run_id, agent_id, queue)` on first message.
- `_stream_router.broadcast(run_id, response_msg)` for each outbound chunk.
- `_stream_router.unregister_handler(run_id, agent_id)` on `done=True`, error,
  or iterator exhaustion.

#### HubService LLM provider

`HubService.__init__` now accepts an optional `llm_provider` argument.
`OrcDaemon` passes `llm_provider=self._llm_provider` when constructing
`HubService`.  When a provider is present, `AgentStream` decodes the payload,
calls `llm_provider.stream(prompt_text)`, and yields each chunk as an
`AgentMessage`.  Without a provider, payloads are echoed verbatim.

#### TUI hub initialization

`OrcChatScreen.on_mount()` calls `_init_hub()`, which attempts
`create_hub(workspace_id="cli", initiator="tui")` once and stores `_hub_id`.
If hub creation fails, the TUI logs a warning and continues with non-gRPC
fallback behavior.

#### _run_command three-branch logic

```
if self._hub_id is not None:
    # gRPC AgentStream path (stream_prompt)
elif self._llm_provider is not None:
    # Local LLM pipeline (_run_agent_pipeline)
else:
    # Sync echo (service.run)
```

The `LoadingIndicator` is shown during both streaming paths and hidden in a
`finally` block.

#### TUI center pane selection and copy behaviour

`MessageLog` now renders conversation output in a read-only `TextArea`
(`id="message-textarea"`) inside the center panel. This enables selectable
output while keeping transcript edits disabled.

Current keybindings and actions:

- `Ctrl+E` → focus the center pane (`action_focus_center`)
- `Ctrl+Shift+C` → copy selected center-pane text (`action_copy_center`)

Copy behavior in `action_copy_center`:

- Uses selected text when available (`get_selected_text()`)
- Falls back to the full center-pane transcript when no selection exists
- If clipboard integration fails, stores the copied payload in
  `_copy_fallback_text` and appends a system message so users can still
  manually recover content

General navigation remains: Enter submits the prompt; Ctrl+K clears history;
Ctrl+C quits.

### AGENTIC-CLI-PROTOBUF — LLM stream retry and model plumbing fixes

This slice fixes three distinct bugs introduced in earlier phases and confirmed
by the 179-test suite passing at zero failures.

#### Problem 1 — `@with_llm_retry` is incompatible with async generators

`@with_llm_retry` is a decorator that wraps a coroutine in a retry loop and
`await`s the coroutine result on each attempt.  An `async def` function that
contains `yield` is an async generator, not a coroutine.  Calling `await` on an
async generator raises `TypeError` at runtime; it does not iterate the
generator.

The decorator was therefore removed from `stream()` on all four provider classes
(`OpenAIProvider`, `AnthropicProvider`, `NvidiaProvider`,
`OpenRouterProvider`).  It is retained on `complete()`, which is a plain
coroutine and compatible with the decorator.

#### Fix — inline retry with pre-yield guard

Each provider's `stream()` method now contains its own retry loop directly.
The loop uses a `_yielded: bool` flag that starts `False` and is set to `True`
the first time a `LLMChunk` is yielded to the caller.

Retry logic:

- Up to 3 attempts total (indices 0, 1, 2).
- Only `LLMRateLimitError` and `LLMTimeoutError` are retried.  Other
  exceptions propagate immediately.
- If `_yielded` is `True` when the error is caught, the exception is
  re-raised immediately regardless of attempt index.  Retrying after a
  partial stream would deliver duplicate content to the caller.
- Backoff on each retriable attempt: `min(1.0 * 2^attempt, 30.0)` seconds
  with full jitter (`random.uniform(0, delay)`).
- After all attempts are exhausted, `_last_exc` is raised.

The `LLMProvider` protocol in `src/llm/provider.py` was updated to reflect the
concrete return type: `stream()` is declared as returning
`AsyncGenerator[LLMChunk, None]` instead of `AsyncIterator[LLMChunk]`.

#### Problem 2 — `chunk.text.encode()` was called on the wrong type

`HubService.AgentStream` previously treated the result of `llm_provider.stream()`
as if each chunk were a `str`.  `LLMChunk` is a dataclass; calling `.encode()`
directly on the chunk object would raise `AttributeError`.

The fix, implemented by IMP in `src/hub/service.py`, is:

```python
chunk_bytes = chunk.text.encode("utf-8")
```

`LLMChunk.text` is the `str` field; `.encode()` is called on that field, not
on the chunk instance.

#### Problem 3 — `stream()` was awaited instead of iterated

`AgentStream` previously called `await self._llm_provider.stream(...)`.
`stream()` is an async generator — it cannot be awaited; doing so raises
`TypeError`.  The fix replaces the bare `await` with `async for chunk in
self._llm_provider.stream(...)`, which is the correct way to consume an async
generator.

#### llm_model plumbing — OrcDaemon to HubService

`HubService.__init__` now accepts an `llm_model: str = ""` parameter, stored
as `self._llm_model`.  When `AgentStream` calls `llm_provider.stream()`, it
passes `model=self._llm_model` so the correct model is selected per-request.

`OrcDaemon.__init__` (in `src/orc/daemon.py`) already accepted an
`llm_model: str = "gpt-4o"` parameter from the previous phase.  It now
forwards that value explicitly when constructing `HubService`:

```python
self._hub_service = HubService(
    storage=...,
    fork_handler=...,
    llm_provider=self._llm_provider,
    llm_model=self._llm_model,
)
```

The `LLM_MODEL` environment variable (default `gpt-4o`, documented in the
Configuration table above) is the end-to-end source of the model identifier.

#### Sensitive-data scanner outcomes (`src/cli/scan.py`)

The scanner emits only redacted values and short fingerprints (SHA-256 prefix), never full candidate secrets.

- Finding output fields: `path`, `line`, `kind`, `redacted`, `fp`
- Redaction format: first 2 characters + masked middle + last 2 characters
- Exit/status behavior:
  - Findings present: prints `policy=Detected candidate secrets; revoke and rotate exposed credentials immediately.` and exits non-zero (`1`)
  - No findings: prints `policy=No verified live secrets detected in repository scope.` and exits `0`

#### Redaction/rotation guidance

If findings are reported, treat any matched credential as exposed:

1. Revoke/disable the credential at the provider.
2. Rotate and issue a replacement credential.
3. Update local/runtime configuration with the replacement value.
4. Remove hardcoded values from tracked files; keep secrets in environment/config injection only.
5. Re-run the scanner until `findings=0` and the no-live-secrets policy line is returned.

### Fork divergence implementation notes (Phase 4)

- `HubService.DetectFork` and `HubService.DecideFork` in `src/hub/service.py` are native `async def` RPC methods and directly `await` `ForkHandler` calls (`handle_detection` / `process_decision`) rather than using a sync bridge.
- `NullStorageBackend.update_fork_decision()` now writes `user_decision` along with `status`, `decided_at`, and `new_hub_id`, so in-memory tests and development runs reflect approved/rejected decisions the same way as PostgreSQL-backed storage.
- The fork list route in `src/api/routes/fork.py` is intentionally pending-only: `GET /api/v1/forks` delegates to `handler.get_pending_forks()` and excludes resolved/decided scenarios by design.
- `tests/integration/test_grpc_fork.py` now asserts both approve and reject decision persistence fields (`status`, `user_decision`, `new_hub_id`, `decided_at`) in addition to child hub creation.
- `tests/unit/test_orc_daemon.py` now covers Redis-enabled startup pending-fork recovery and verifies warning-clean lifecycle shutdown for the detector listener task.
- Auth caveat still applies to fork flows: there is no authentication/authorization enforcement in current REST or gRPC surfaces.

## Limitations

- Conversation state lives only inside one Python process
- Metadata is validated on `RunCommand` but is not consumed by the local backend yet
- The local backend is deterministic test scaffolding, not a real model/runtime integration
- `replay-sla` shares the CLI binary but does not participate in the `run` conversation flow
- Each `OrcDispatch` instance maintains its own session state via the injected `AgenticCliService`; do not share a single instance across concurrent request handlers unless shared session counters are intended
- **No automatic connection retry** — `asyncpg` connection failures are not retried. This is a deliberate slice boundary.
- **No authentication/authorization layer yet** — gRPC and REST surfaces do not enforce caller identity or policy checks in the current slice.
- `db_credentials` config field is reserved but not wired into storage initialisation.

### Architecture Overview

```
TUI (Ink/React) ──HTTP REST──→ POST /api/v1/run ──→ OrcDispatch
                                    │
                                    ├──→ dispatch_run (local backend)
```

### MCP Tooling

The agentic runtime includes MCP (Model Context Protocol) integration for external tool discovery and invocation.

#### MCPManager

`MCPManager` (in `src/agentic/mcp_manager.py`) manages connections to MCP servers via SSE transport:

- **Config Loading:** Reads `.mcp.json` from project root or configurable path
- **Tool Discovery:** Returns tools in LLM-compatible format (`{"type": "function", "function": {...}}`)
- **Tool Invocation:** Calls tools via `session.call_tool(name, arguments)`
- **Retry Logic:** 3 retries with 1s delay on connection failures

#### Configuration

Create `.mcp.json` in the project root:

```json
{
  "mcpServers": {
    "server-name": {
      "url": "http://localhost:8080/sse"
    }
  }
}
```

#### Usage

```python
from src.agentic.mcp_manager import MCPManager

manager = MCPManager()
await manager.initialize()

# Discover tools
tools = await manager.discover_tools()

# Invoke a tool
result = await manager.invoke_tool("tool_name", {"param": "value"})

await manager.shutdown()
```

See `docs/mcp-integration.md` for full API reference and examples.
